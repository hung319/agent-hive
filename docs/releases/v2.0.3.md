# v2.0.3 — Agent cài global + bỏ hai dependency `@sparkleideas`

Bản **2.0.3** trả agent về đúng hành vi v1 (cài **một lần ở global**, không rải file vào từng project), thay `hive_code_edit` và memory bằng engine của Hive nên **không còn dependency `@sparkleideas`** nào.

## Sửa

### 1. Agent chỉ cài một lần ở global (giống v1)

- V2 sinh agent qua file `<config>/agents/<id>.md`. Bản 2.0.0–2.0.2 ghi vào `<project>/.opencode/agents/`, nên **mỗi project mở ra đều có thêm 8 file agent** và `.opencode/agents` của project che mất cấu hình global.
- Nay ghi vào `$XDG_CONFIG_HOME/opencode/agents` (mặc định `~/.config/opencode/agents`), cùng chỗ với `agent_hive.json`, skills và packages. Đổi chỗ được bằng biến môi trường `OPENCODE_AGENTS_DIR`.
- Khi setup, plugin **dọn file agent do bản 2.x cũ để lại** trong `<project>/.opencode/agents/` (chỉ đúng tên 8 agent của Hive; agent do bạn tự viết trong thư mục đó được giữ nguyên). Thư mục `agents` rỗng thì xoá, `.opencode` vẫn để lại nếu còn file khác.
- Hệ quả: mở project mới không còn sinh file; sửa `agent_hive.json` (model, custom agent, auto-load skill) được áp cho mọi project ở lần chạy sau.

### 2. `hive_code_edit` và memory dùng engine của Hive (bỏ `@sparkleideas/*`)

- `@sparkleideas/agent-booster` gần như không còn được cập nhật, và cách nó được gọi lại mong manh: bản 0.2.34 chỉ export class `AgentBooster` (phương thức `apply` nằm trên prototype) cùng một hàm `apply` tên riêng; code cũ lấy module (một function object) làm instance nên rơi vào `Function.prototype.apply`, ném `Cannot call a class constructor` rồi âm thầm thay chuỗi.
- Nay `hive_code_edit` dùng engine có sẵn trong Hive:
  - khớp **chính xác** trước (đường nhanh, giống hệt trước đây);
  - nếu chỉ khác thụt lề thì khớp theo dòng, **giữ thụt lề của file** và giữ độ sâu tương đối của từng dòng trong đoạn sửa;
  - không khớp thì trả lỗi kèm dòng gần giống nhất và **không ghi file** (không còn nửa vời).
- Kết quả nói rõ matcher nào đã chạy: `Applied via exact (confidence 1.00)` hoặc `Applied via fuzzy_indent (confidence 0.80)`.
- `hive_booster_status` báo `builtin`, `capabilities { apply, lazyApply }`; `hive_lazy_edit` ghép marker `// ... existing code ...` bằng code của Hive; không còn bước cài package, không còn `require` động theo `HOME`.
- Memory: **bỏ hẳn `@sparkleideas/memory`**. Hive tự lưu entry dạng sharded JSON (`~/.config/opencode/hive/vector-memory/`) với quality guard + dedup, tìm bằng text search; `hive_vector_status` báo `Built-in text search (sharded)`. Memory cũ vẫn đọc được, dữ liệu không phải migrate.

### 3. Permission trong agent md không còn dòng trùng

- Alias v1 (`write`/`patch` → `edit`, `task`/`delegate` → `subagent`, `bash` → `shell`) sinh ra nhiều dòng y hệt trong frontmatter (`edit` ×2, `subagent` ×2). Nay mỗi action V2 chỉ một dòng.

### 4. Nạp plugin không còn cài package (CI xanh trở lại)

- Nguyên nhân gốc của hai run đỏ ở 2.0.3: `bun test` không thấy workspace link (xem bullet workflow bên dưới), **cộng thêm** việc nạp plugin chạy **auto-install ngay trong `setup()`**, nên mỗi lần test mở plugin là một lần shell ra package manager. Trên CI (chỉ có Bun, không có Node) log `/bin/sh: 1: npm: not found`; ở máy có npm thì một gói cài hỏng vẫn có thể làm lần nạp đó khác đi — thứ mà test không bao giờ nên phụ thuộc.
- Nay **setup plugin không đụng mạng**: `bun-pty`, `auto-cr-cmd`, `btca` được cài ở **lần dùng tool đầu tiên** (`ensureToolInstalled`), hỏng thì tool đó tự degrade như trước. Mở plugin trong test, trong project hay lúc sửa code đều không gọi mạng.
- `tool-installer` cài **từng gói một**, log `Installed via npm: ...` và `Unavailable: ...` riêng từng package, nên một dependency chết (ví dụ `agentdb@alpha` chưa publish kèm `dist/`) không kéo cả cụm. Không có `npm` lẫn `bun` trên PATH thì bỏ qua **im lặng** thay vì cảnh báo mỗi lần nạp.
- Hai workflow đưa `bun` vào `GITHUB_PATH`: setup-bun chỉ đặt PATH cho step của chính nó, nên `bun test` từng chạy bằng một bun khác với `bun install` và không thấy workspace link (`Cannot find module '@opencode/plugin'`). Workflow Release cũng bỏ lần `npm install -g npm@11` bị lặp trong bước publish.
- Test `ensureCodegraphInit` chấp nhận skip khi máy không có `codegraph` trên PATH (PATH của CI khác máy dev).

## Lưu ý khi nâng cấp

- Chạy `opencode plugin update` rồi khởi động lại server. Lần mở đầu tiên ở mỗi project sẽ dọn `.opencode/agents/*.md` cũ (nếu có).
- Nếu bạn từng tự sửa tay file agent do plugin sinh (ví dụ `~/.opencode/agents/zetta.md`), hãy chuyển nội dung đó sang `agent_hive.json`/custom agent hoặc `~/.config/opencode/agents/<tên-khác>.md`: file trùng tên sẽ bị ghi đè mỗi lần setup.
