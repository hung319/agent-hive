# v1.20.3

## Fixes

### LSP hover/diagnostics wrong branch
- `getLspClientForFile` thất bại do `resolveServerPath` vẫn trỏ `.../lsp/bin/typescript-language-server` (cũ) thay vì `.../node_modules/.bin/...` → `checkAndInstall` báo `ready` nhưng tool vẫn `success:false` với message ready nằm trong `error`. Fix: `lsp/manager.ts` đổi `SERVER_COMMANDS` resolve theo thứ tự `node_modules/.bin` → legacy `bin` → PATH (kiểm tra `fs.accessSync` + `X_OK`); `tools/lsp.ts` cho 5 tools (`rename/goto/references/diagnostics/hover`) retry `getLspClient` sau khi `checkAndInstall` ready, chỉ error khi vẫn null với message rõ ràng.

### Vector backend dao động
- `vector-memory.ts`: `memoryInitPromise` latch sau khi race với tool-installer (fail 1 lần kẹt fallback đến restart), `memoryInstance` không gán khi package expose `init` ở top-level, `getMemoryStatus` lật sang fallback khi `stats()` probe fail, và success paths thiếu `fallback:false`. Fix: reset promise khi fail để retry, gán instance ở mọi branch, explicit `fallback:false` cho vector success, status vẫn báo `type:'vector'` khi probe fail.

### agent-booster không nhận global install
- `initBooster` chỉ check hive packages + `require('@sparkleideas/agent-booster')` → miss global `npm root -g`. Fix: `resolveBoosterPackage()` thử hive → global npm root (`npm root -g` cached) → cwd → `require.resolve`; `tool-installer.ts` thêm `getGlobalNpmRoot()` và `isModuleResolvable` check global root; `getBoosterStatus` đọc version từ module đã load thay vì bare re-import.

### Audit trùng lặp (không xóa code, chỉ báo cáo)
- Đã quét toàn repo: **không pruned tự động** ở 1.20.3. Dead files phát hiện (9 files zero importer) đã giữ lại để bạn duyệt. Chi tiết overlap: LSP có 2 `LspManager` khác nghĩa + 3 bảng lang→server + 2 installer; Memory có 4 abstraction overlap (`block`/`typed`/`journal`/`vector`); `autoSaveProjectMemory` bypass block tool; `agentMode unified/dedicated` byte-identical. Sẽ prune riêng khi bạn confirm.
